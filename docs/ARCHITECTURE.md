# المعمارية

- **تطبيق واحد، ثلاثة أدوار** (`Role.CLIENT / BROKER / DEVELOPER`): الدور يُختار عند التسجيل ويتحكم في التبويبات والشاشات (مثلًا: المطور يرى «إعلاناتي» و«الحجوزات»، الوسيط يرى «العمولة» ويُدخل بيانات العميل قبل التفاوض).
- **UI:** Jetpack Compose + Material 3، تنقل بـ Navigation Compose (مسارات نصية في `Nav.kt`). نصوص ثنائية اللغة عبر `t("عربي","English")` واتجاه RTL/LTR حسب اللغة.
- **البيانات:** `Repo` (Object) يحتفظ بحالة Compose ويحفظ JSON في SharedPreferences. الصور تُنسخ مضغوطة إلى `filesDir/images` (بدون صلاحيات تخزين).
- **الدفع:** واجهة `PaymentGateway` — الافتراضي `DemoGateway`.
- **الخادم (مطلوب للإنتاج):** استبدل `Repo` بطبقة شبكة (REST/GraphQL) + مصادقة (OTP عبر مزود SMS) + تخزين صور + لوحة مراجعة إعلانات + إشعارات FCM + بوابة دفع. الواجهات الأمامية لن تتغير كثيرًا.
- **التحديثات:** `UpdateChecker` (Play In-App Updates) + شاشة «ما الجديد» من `Changelog.kt`.

## الفروق عن التصميم (قرارات مقصودة)
- الصور: رسومات مولّدة بالكود بدل صور المباني (لتفادي حقوق الملكية)؛ الإعلانات الحقيقية تعرض صور المعلن.
- الخطوط: خط النظام (IBM Plex Sans Arabic غير مضمّن لأنه يحتاج ملفات TTF؛ أضفها في `res/font` وعدّل `Theme.kt`).
- الأولويات: اختيار بالأزرار بدل السحب والإفلات.
- «مستشارك الذكي»: مساعد بحث بقواعد بسيطة (ليس ذكاءً اصطناعيًا) وهذا مكتوب داخل الشاشة.
- أزرار Google/X/Apple: واجهة فقط وتعرض رسالة «غير مفعّل» (تحتاج OAuth).
- أخبار العقارات والبورصة العقارية: «قريبًا» (لا يوجد محتوى في التصميم).
