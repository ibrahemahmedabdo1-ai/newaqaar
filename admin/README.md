# لوحة تحكم بوابة العروض + الـ API

Next.js (App Router) + TypeScript + Prisma + PostgreSQL (Neon) — تُنشر على Vercel، وتخدم تطبيق الأندرويد عبر `/api/v1`.

> **حالة الاختبار (بصراحة):** الكود كله اتكتب واتفحصت صياغته (TypeScript syntax) لكن **لم يُبنَ ولم يُشغَّل** في بيئة الكتابة (مفيش إنترنت لتنزيل الحزم ولا قاعدة بيانات). أول بناء حقيقي هيكون على GitHub Actions (`Admin panel CI`) وعلى Vercel. لو ظهر خطأ ابعته وأصلحه.

## الإعداد خطوة بخطوة

### 1) قاعدة البيانات (Neon)
1. أنشئ مشروعًا على [neon.tech](https://neon.com) (منطقة قريبة منك).
2. انسخ رابطين: **Pooled** (فيه `-pooler`) → `DATABASE_URL` وأضف في آخره `&pgbouncer=true&connect_timeout=15`، و**Direct** (بدون pooler) → `DIRECT_URL`.

### 2) أسرار GitHub (لإنشاء الجداول)
في الريبو: Settings ← Secrets and variables ← Actions ← New secret:

| Secret | القيمة |
|---|---|
| `DATABASE_URL` | الرابط Pooled |
| `DIRECT_URL` | الرابط Direct |
| `SEED_ADMIN_EMAIL` | بريد أول مدير |
| `SEED_ADMIN_PASSWORD` | كلمة مرور قوية (12+ حرفًا) — **لا توجد كلمة مرور افتراضية** |
| `SEED_ADMIN_NAME` | اسمك (اختياري) |

ثم Actions ← **Database setup (Neon)** ← Run workflow (يُنشئ الجداول + أول مدير + المحتوى الأولي).

### 3) النشر على Vercel
1. Vercel ← Add New Project ← اختر الريبو.
2. **Root Directory = `admin`**. (Framework: Next.js تلقائي.)
3. Environment Variables (من `.env.example`):
   - `DATABASE_URL`, `DIRECT_URL`
   - `ADMIN_JWT_SECRET`, `API_JWT_SECRET` (نصان عشوائيان مختلفان 32+ حرفًا) — مثال توليد: `openssl rand -base64 48`
   - `CRON_SECRET` (نص عشوائي) — لتشغيل مهمة رفض العروض المنتهية يوميًا (`vercel.json`)
   - `OTP_PROVIDER` = `console` للتجربة أو `twilio` للإرسال الحقيقي (+ `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`)
   - `OTP_DEBUG` = `true` + `ALLOW_OTP_DEBUG` = `true` **للتجارب فقط** (يرجع الرمز في الاستجابة ويظهر في التطبيق، ويحتاج الاثنين على Vercel Production) — احذفهما قبل الإطلاق
   - `PAYMENT_PROVIDER` = `demo` و`ALLOW_DEMO_PAYMENTS` = `true` **للتجارب فقط** (في الإنتاج تُرفض المدفوعات التجريبية ما لم تضبط هذا المتغير)
   - `BLOB_READ_WRITE_TOKEN`: من Vercel ← Storage ← Blob (لرفع صور الإعلانات)
4. Deploy. افتح `https://<مشروعك>.vercel.app/login` وسجّل بحساب الـ Seed.
5. اختبر: `https://<مشروعك>.vercel.app/api/health` ← `{"ok":true,"db":"up"}`.

### 4) ربط التطبيق
في ريبو GitHub: Settings ← Secrets and variables ← Actions ← **Variables** ← New variable:
- `API_BASE_URL` = `https://<مشروعك>.vercel.app` (بدون `/` في آخره)

ثم أعد تشغيل **Build Android APK**. الـ APK الجديد يتصل باللوحة (وإن تُرك المتغير فارغًا يعمل بالوضع التجريبي المحلي).

## جاهزية الإنتاج
لوحة المؤشرات فيها بطاقة **«جاهزية الإنتاج»** تعرض ما زال تجريبيًا (OTP عبر console، الدفع demo، OTP_DEBUG، عدم تفعيل Blob/Cron، بيانات الدعم...). اجعلها فارغة قبل الإطلاق.

## الأمان (ما نُفّذ وما عليك)
- تحديد معدل الطلبات داخل التطبيق (مخزَّن في قاعدة البيانات) على: الدخول، التسجيل، OTP، استعادة كلمة المرور، رفع الصور، الدعم، العروض. فعّل أيضًا Vercel Firewall.
- `.github/dependabot.yml` يفتح لك Pull Requests أسبوعية لتحديثات Next.js وباقي الحزم (والأمنية منها) ومكتبات الأندرويد وGitHub Actions — راجعها وادمجها.
- كلمات المرور bcrypt، جلسات الأدمن JWT في Cookie `httpOnly` + `sameSite=lax` (+ `secure` في الإنتاج)، قفل الحساب بعد محاولات فاشلة، إبطال الجلسات عند تغيير الدور/كلمة المرور.
- فحص الصلاحية داخل **كل صفحة وكل Server Action** (لا نعتمد على middleware).
- كل إجراء إداري يُسجَّل. اطلاع المشرف على المحادثات يُسجَّل.
- OTP: حد 5 طلبات/ساعة و30 ثانية بين الطلبات، و5 محاولات تحقق.
- **عليك:** تحديث Next.js باستمرار (تصدر ثغرات أمنية دورية) — راجع نشرات الأمان وشغّل `npm update next`. فعّل Vercel Firewall/Rate limiting للـ API. استخدم HTTPS فقط. دوّر الأسرار دوريًا.
- صور الإعلانات والمحادثات تُخزَّن بروابط عامة غير قابلة للتخمين على Vercel Blob.
- الدفع: `DemoGateway` فقط. اربط بوابة حقيقية في `src/lib/payments.ts`، واستخدم **Google Play Billing** لاشتراك المزايا الرقمية.

```bash
cd admin

npm install
npx prisma db push

npm run dev
```
